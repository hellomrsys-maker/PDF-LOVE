# PDFLove on Cloudflare (Workers static assets)

`wrangler.jsonc` (repo root) was auto-generated by Cloudflare's GitHub
integration when the repo was connected — it serves everything in
`frontend/` as static assets. `frontend/_headers` was added on top of that
to restore the security headers (CSP, X-Frame-Options, etc.) that
`frontend/nginx.conf` provides in the Docker/self-hosted path — Cloudflare's
static-asset serving never reads nginx.conf, so without `_headers` those
protections would silently be missing on this deployment.

## What works out of the box

All ~97 on-device tools, the assistant, the SEO guides, the install button,
offline licensing — everything that doesn't need the optional backend.
Static hosting is static hosting; nothing about PDFLove's on-device
architecture cares which host serves the files.

## What's different from the Docker/nginx path

`nginx.conf` also reverse-proxies `/api/*` to a backend container so the
browser only ever talks to one origin. **Cloudflare's static-asset serving
does not do this automatically** — there's no backend container alongside
it. If you want the server-assisted tools (OCR via a real backend, full-
fidelity Office conversion, etc.) to work on a Cloudflare-hosted deployment,
you have two options:

1. **Host the backend elsewhere** (a VPS, per `deploy/PRODUCTION.md`) and
   point the frontend at it from the browser console or your own build step:
   `localStorage.setItem('pdflove.apiBase', 'https://your-backend-domain')`
2. **Add a Cloudflare Worker route** that proxies `/api/*` to your backend,
   mirroring what `nginx.conf`'s `location /api/` block does — this isn't
   set up yet; ask if you want it built.

Neither is required for the free, on-device experience — this only matters
if you specifically want the optional server-assisted tools working on a
Cloudflare-served deployment.

## Verifying it after a deploy

Confirm the headers actually landed (Cloudflare's `_headers` matching can
have edge cases worth double-checking against the real deployment, not just
this file's contents):

```bash
curl -sI https://your-domain/index.html | grep -i content-security-policy
```

You should see the same CSP value as `frontend/nginx.conf`'s. If it's
missing, check the Cloudflare Pages/Workers dashboard's deployment log for
whether `_headers` was picked up from `frontend/`.

## Branches

Cloudflare's GitHub integration created its own branch
(`cloudflare/workers-autoconfig`) when first connected. `wrangler.jsonc`
and the `.gitignore` additions from that branch are now folded into this
one — check your Cloudflare Pages/Workers project settings for which
branch it's actually configured to build from, and point it at this one
if it's still watching the auto-created branch.
