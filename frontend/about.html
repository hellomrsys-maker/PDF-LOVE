About PDFLove

PDFLove exists because "upload your confidential document to our server" is a strange thing to ask, and for most PDF jobs it is not even necessary.

The idea

Browsers have been able to do serious work for years. WebAssembly runs the same C and C++ libraries that a server would use — qpdf for PDF surgery, Tesseract for OCR, real AES-256 for encryption — at close to native speed, on the machine already sitting in front of you. Once you accept that, sending a file to a server to have its pages reordered looks like an odd detour.

So PDFLove keeps the file where it already is. Your device supplies the processing power and the memory; we supply the logic. That single decision is what removes the upload wait, the file size cap, the daily limit, the account, and the privacy question all at once.

What that means in practice

  • There is no server holding your documents, because there is no upload.
  • There is no per-file cost to us, so there is no reason to meter you.
  • An installed copy keeps working on a machine with no internet connection at all.
  • We cannot hand over your files to anyone, because we never have them.

Being honest about the limits

A few jobs really are better on a server — full-fidelity Office conversion needs LibreOffice, and deep compression needs Ghostscript. Rather than pretend otherwise, those tools are clearly marked "server-assisted", are switched off by default, and run on a backend you host yourself. The app never contacts one unless you tell it to.

PDFLove is also a web app, which means its code is delivered to your browser to run. That is what makes local processing possible, and it also means the code is inspectable — you can read exactly what it does.
