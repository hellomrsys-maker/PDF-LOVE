The on-device guarantee, stated precisely

On-device tools read your file with the browser's File API, process it in page memory, and hand the result to the browser's download mechanism. No network request carries file contents or filenames. This is verifiable: pick a file and watch the Network tab — nothing fires while it is being processed.

We word it this way deliberately. "We don't store your files" is a promise about someone's conduct. "Your file is never transmitted" is a property of the system that you can check for yourself, and that an automated test checks on every deploy.

PDF Love itself sends nothing. There is no analytics, no telemetry and no "which platform is this user on" ping — not even for advertising. An advert network already sees the user-agent and IP when it serves an advert, so there is nothing for us to add and no reason to weaken the claim.

Where the guarantee does not apply

Honesty matters more than a clean claim:

  • Server-assisted tools (10 of 104) do transmit the file you submit. They appear only when a backend is reachable and are labelled in the interface. That backend logs no file contents or filenames and deletes per-request temporary files as soon as the response is built. In the desktop app that "backend" is on your own machine, bound to loopback.
  • Currency converter requests live rates. No file or personal data is sent; as with any request, your IP is visible to that provider.
  • On-device AI models download once from a public model host, then run offline from cache.

Application security

  • Strict Content-Security-Policy. Every library is served from our own origin; the tool pages depend on no third-party script.
  • object-src 'none', frame-ancestors 'none', X-Frame-Options: DENY, nosniff.
  • Encryption uses qpdf compiled to WebAssembly — real AES-256, not an obfuscation trick.
  • The optional backend runs as a non-root user with no-new-privileges, per-endpoint rate limits and a request size cap.
  • Page rendering is capped at 8192px to blunt decompression-bomb inputs, and heavy tools estimate memory before starting.

Reporting a vulnerability

Email security@pdflove.co.in with enough detail to reproduce. Please give us a reasonable window to ship a fix before publishing.

In return: we will acknowledge within 3 business days, keep you updated, credit you if you would like, and we will not pursue legal action over good-faith research that respects user privacy and does not degrade the service for others.

Out of scope: reports produced solely by automated scanners with no demonstrated impact, and anything that requires an already-compromised device.
