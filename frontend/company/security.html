Security

The architecture is the security story: for 97 of 104 tools there is no server to breach, because your file never reaches one.

The on-device guarantee, stated precisely

On-device tools read your file with the browser's File API, process it in page memory, and hand the result to the browser's download mechanism. No network request carries file contents or filenames. This is verifiable: developer tools → Network tab → use a tool → nothing fires.

We state it this way deliberately. "We don't store your files" is a promise about someone's conduct. "Your file is never transmitted" is a property of the system that you can check for yourself.

Dockbench itself sends nothing. There is no analytics, no telemetry, and no "which platform is this user on" ping — not even for advertising. An ad network already sees the platform, user agent and IP when it serves an ad, so there is nothing for us to add and no reason to weaken the claim.

Where the on-device guarantee doesn't apply

Honesty matters more than a clean claim:

  • Server-assisted tools (7 of 104) do transmit the file you submit. They appear only when a backend is reachable and are labelled in the UI. That backend logs no file contents or filenames, and deletes per-request temporary files as soon as the response is built. In the desktop app that "backend" is on your own machine, bound to loopback.
  • Currency converter requests live rates. No file or personal data is sent; as with any network request, your IP is visible to that provider.
  • On-device AI models download once from a public model host, then run offline from cache.

Application security

  • Strict Content-Security-Policy; no third-party scripts and no CDN dependency — every library is served from the same origin.
  • object-src 'none', frame-ancestors 'none', X-Frame-Options: DENY, nosniff.
  • Encryption uses qpdf compiled to WebAssembly — real AES-256, not an obfuscation trick.
  • The backend runs as a non-root user with no-new-privileges, per-endpoint rate limits, and a request size cap.
  • Page rendering is capped at 8192px to blunt decompression-bomb inputs, and heavy tools estimate memory before starting.
