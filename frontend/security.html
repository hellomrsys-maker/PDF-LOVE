Security

The strongest security property PDFLove has is structural: your documents are not on our servers, because we never receive them.

Processing model

On-device tools read your file with the browser's File API, process it in page memory, and return a download. The bytes never enter a network request. Closing the tab discards everything. There is no server-side copy, no temporary upload directory and no retention window, because there is no upload.

Encryption

Protect PDF applies genuine AES-256 encryption through a WebAssembly build of qpdf, running locally. The password you type is used on your device and is never transmitted or stored. We cannot recover it — if you lose it, the document cannot be opened.

Transport and page security

  • Served strictly over HTTPS.
  • A strict Content-Security-Policy, plus X-Content-Type-Options: nosniff, X-Frame-Options: DENY and a restrictive Permissions-Policy.
  • Every library is self-hosted. The app loads no third-party scripts, so there is no CDN that could be compromised to alter what runs on your document.

The optional backend

If you enable server-assisted tools, only the file you explicitly submit to that tool is sent, to a backend you have pointed the app at. That backend logs no file contents or filenames, works in a per-request temporary directory that is deleted as the response is built, and runs as a non-root user in a container. You can host it yourself and read every line of it.

Reporting a vulnerability

Please report privately to security@pdflove.co.in before disclosing publicly. Include the steps to reproduce and the affected version. We will acknowledge, keep you updated while we investigate, and credit you when a fix ships if you would like us to.

Please do not run automated scanners against the production site, and do not test with anyone else's data.
