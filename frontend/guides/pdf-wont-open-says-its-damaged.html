What "damaged" usually means

Very often the content of the file is completely fine and its index is not. Every PDF ends with a cross-reference table: a directory recording the byte offset of every object in the document, so a reader can jump straight to page 90 without parsing the first 89. Readers trust that table absolutely. If the offsets no longer match where things actually are, the reader cannot find the page tree, concludes the file is unreadable, and shows you an error — while the pages themselves sit in the file, intact and entirely recoverable.

The usual causes are dull and mechanical: a download that stopped short, a program that crashed while saving, a USB drive pulled out mid-write, a file transferred in text mode instead of binary, or a sync client that uploaded a half-written file. In each case the damage is structural rather than to the content.

How repair works

A repair pass ignores the broken index entirely. It scans the file from the beginning looking for object definitions — they have a recognisable shape — collects everything still parseable, works out which objects form the page tree, and writes a fresh cross-reference table describing where things really are. The output is a new file whose index matches its contents, which readers will open normally.

What repair cannot do is invent data. If a download stopped at 60%, the last 40% of the objects are not in the file and no tool of any kind will produce them. Recovering the first 60% is the best available outcome, and frequently a good one.

Check these before repairing

  • Is it actually a PDF? Some downloads save an HTML error page under a .pdf name. Open it in a text editor: a real PDF begins with %PDF- in the first few bytes.
  • Is it complete? Compare the size against the source. A file noticeably smaller than expected is truncated, and repair will recover only what arrived.
  • Is it zero bytes? Then there is nothing there. Get it again from the source.
  • Does another reader open it? Browsers, phone readers and desktop applications tolerate different faults. A file one refuses may open elsewhere, and if it does, printing it to a new PDF from that reader is a repair in itself.

Reading the result honestly

After a repair, check the page count first — it is the fastest signal. Matching the original means the structure was the whole problem and you are done. Fewer pages means some objects were unrecoverable, and the missing ones are almost always at the end, consistent with a truncated file. Then page through and look for blank pages or missing images, which indicate individual objects that could not be salvaged even though the page around them survived.

If the recovery is partial and the document matters, go back to the source before settling for it: re-download it, ask the sender to resend it, or check whether your backup or version history has an earlier copy. A complete original always beats a good repair.

Worth knowing: if the file came from someone you do not know and will not open, be a little careful where you take it. "Free PDF repair" sites want you to upload a document that may well be confidential, to a server you know nothing about, to fix a problem that is mostly bookkeeping. Repairing on your own device avoids the question entirely.

This isn't magic — if the underlying data is truly gone, no tool (cloud or local) can bring it back. But for the common case of a broken internal structure (an interrupted download, a bad save), a repair pass often recovers the file. Doing this on-device means a possibly-sensitive document isn't uploaded to a random "PDF repair" website in the process.
